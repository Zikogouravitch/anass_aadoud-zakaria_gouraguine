## Circuit GitHub

1. Chaque rédacteur travaille sur sa propre branche (`semaine1/descriptif`, `semaine1/dataset`, `semaine1/maquette`, `semaine1/pipeline`) et ouvre une pull request.
2. Le relecteur vérifie les critères d'acceptation du livrable, commente dans la pull request, puis l'approuve.
3. Une pull request n'est fusionnée qu'après approbation.
4. Une fois les quatre livrables fusionnés, le coordinateur pose l'étiquette `semaine1-remis` et prévient l'enseignant.
